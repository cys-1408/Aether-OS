# Action Ledger
Append-oriented SQLite (ledger/schema.sql) partitioned per user. Entry fields per protocols/schemas/action-ledger-entry.schema.json: request, plan, capability calls, redacted params, permission decision, confirmation event, execution result, verification, errors, affected resources, rollback availability, retention category. Secrets never enter the ledger (redaction pre-insert). Users get readable history (Miso panel → activity; Recovery Center → export), retention (default 90 d) and per-user clear. The agent cannot erase or alter protected entries; hash chaining (security/audit/audit_integrity.py) makes tampering detectable.
